## 多源核对如何避免相互抄错

1. 以[开发者官方Demo页面](https://hoochoo-game-studios.itch.io/no-umbrellas-allowed)提供的Windows包为一手数据，实际检查PlayerSettings为`1.0.5 Demo`；源码分析仅在临时目录，产品规则是独立TypeScript实现。
2. 将官方更新记录、英文/韩文说明、多份不同时期玩家指南和用户视频分开编号。攻略中的经验比例不能直接升级为确定公式。
3. 将可疑解释反查到原生物品、脚本、头像字典或直接DLL调用。比如鳄鱼画的“帆布”人工注释被真实纸张纹理对比推翻；红Ajik贷款也通过头像字典和AddLoanOfferData排除了Bluebird误配。
4. 对有版本差异、未知种子或视频剪切的地方保留未知，不能用录像答案填入运行时。

详细记录：[物品](research/OFFICIAL_ITEM_DATA.md)、[顾客与专属脚本](research/DEMO_CUSTOMERS.md)、[议价](research/NEGOTIATION_DEMO_FACTS.md)、[经济](research/DEMO_ECONOMY_FACTS.md)、[声望](research/DEMO_REPUTATION_FACTS.md)。

## 验收方式

- `src/system.test.ts`对访问`price/final/quotes/sourceCash/sourceCashAfter`的运行时代码直接抛错。三种策略都必须走完53来访及6次日结，并逐动作检查钱和物品守恒。
- 独立测试包括错误鉴定、全部拒绝、随机货架操作、议价中切换库存、贷款/逾期失败、修后出售、挑战30次和存档重放。
- `scripts/verify-free-play.mjs`只用真实UI输入，测试改价成交、拒绝后换人、重复点击、未完成议价保存、刷新恢复、完整故事/挑战结束以及日历双分支。
- 手册单独逐页截图，与原裁切进行像素对照；这项结论不扩大到全屏。
- 七条自由路径报告分别记录实际构建文件；书页、库存、工具在此前的同UI构建上完成，构建关联与最后修复范围在最终汇总中单独说明。旧录像路线测试保留为历史参考，不再作为完整性依据。

最新实际结果由 `artifacts/qa/final-system-verification.json` 汇总；系统路径报告在 `artifacts/audit/system-campaigns.json`，真实UI报告在 `artifacts/qa/free-play/report.json`。这些报告证明所列行为，不能证明任意尚未覆盖的输入组合。

本次最终构建 `index-BAp3msdd.js`：158项测试通过，7条真实UI路线通过且无浏览器错误；21页手册裁切区域逐像素一致，48个拖卡热点实测通过。另有库存5项检查、6次工具读数截图及贷款组件6种状态记录。具体构建和范围以汇总JSON为准。

## 仍不能称为“完全一样”的原因

- 完整版1.0.5与Demo不等于同一发行包。缺少原始存档、全日程及进程随机状态，不能还原全部随机顾客、初始开价与隐藏历史。
- 给定视频有多处剪辑，后续库存和余额变化的来源不全。当前保持真实连续经营；缺货顾客会离开，不自动补发录像物品。
- 原作更长剧情、完整结局、拍卖/多件商品等未在当前片段完成重建；Challenge的30次来访内容池是研究原型规则。
- 街道GEM入口目前接到可用维修交互，其独立内景及与真正维修店的路由还没有按原作重建。
- 现有NPC对白的一部分为对应分支的英文转述；日记目前呈现实际财务信息，未重建所有条件化故事日记。
- 原生字体/组件改善了UI，但浏览器与Unity的字形栅格、光照和动态布局还存在差异。只有已单独报告的21页书图拥有逐像素证据。

因此可交付的是有持续状态和自由路径验收的研究原型，而非以“100%”作为结论的完成版。
