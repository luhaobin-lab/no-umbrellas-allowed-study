# 议价与顾客反应交叉核对

核对日期：2026-09-21。目标：用户录像中的 PC 1.0.5；后续版本资料不能直接当作该版本的数值真相。这里只记录研究证据与实现约束，不声称已经还原原版算法。

后续更新：已通过作者公开下载页取得 `1.0.5 Demo` 并静态核对部分规则。以下“unknown”是公开网页阶段的结论；新增数学证据、与攻略的冲突和仍未实现的管线见 [NEGOTIATION_DEMO_FACTS.md](NEGOTIATION_DEMO_FACTS.md)。

## 结论

当前引擎把录像成交价当作接受门槛，会忽略本次鉴定、顾客期望与先前报价。公开资料直接反对这种模型。应分别维护物品真实属性、公开鉴定、私有鉴定、顾客已接受的信息与议价状态。具体心理系数、随机概率和绝大多数阈值仍是 **unknown**。

## 顾客分类：可建行为分支，不能假装名称/系数来自源码

以下均为 G2 的作者分类，名称不是确认过的内部枚举。全部低于“1.0.5实测”级别；只适合作为待验证假设：

| 分类 | 作者观察 | 数值地位 |
| --- | --- | --- |
| Standard | 接受正确信息；可能立即成交、要求加价、给出反报价或离开。 | 60%起手与中点报价是策略，非保证。 |
| Poor listeners | 接受升值卡，拒绝贬值卡。 | 与P2/P3方向互证，精确怒气阈值未知。 |
| Fearless | 戴徽章、对鉴定冷淡。 | 作者报告20%可成交，单来源，待验证。 |
| Frightened | 戴徽章、惧怕升值；过多正面卡可离店。 | 作者报告第二张正面卡导致离店，待验证。 |
| Sentimental | 不情愿卖出，少量低报价即离开。 | 作者报告两次低报价，接受比例变化，待验证。 |
| Fixies | 拒绝主观信息，接受正确客观信息。 | 约70%反报价为后期经验，不用于当前录像硬门槛。 |

G2建议110%挂牌，但其评论也报告更高成交。与G1合看只能确认“可能高于估值卖出”，不能生成统一最高售价。G2称通常取中点能成交；O1与P1说明顾客/交易类型并不一致，因此不得实现全局 `accept(midpoint)`。

## 已确认行为与未确认参数

| 系统关系 | 可实现约束 | 仍未知 |
| --- | --- | --- |
| 鉴定→议价 | 公开信息改变本次估值；顾客不必认可全部正确卡。 | 认可/拒绝的精确人格分类和卡覆盖规则。 |
| 私有卡 | 不作为已向卖家公开的说服依据；错误私有卡须能在出售鉴定时产生后果。 | 侦测/举报概率、额度门槛、适用事件。 |
| 价格往返 | 收购有接受、要求更好报价、反报价、拒绝离店。 | 底价生成、随机种子、回合数、情绪累积公式。 |
| 普通橱窗出售 | 依实际库存、标价和本次买家请求；支持接受或拒绝压价。 | 客流中买家选择概率、购买意愿分布。 |
| 声誉 | 拆开鉴定/推荐/好感；鉴定质量在出售时结算，效果动态更新。 | 每次增减量、各等级边界及全部覆盖关系。 |
| 时间与耐心 | 不把玩家快速操作当作无限刷客流；区分实际时间与被冒犯次数。 | 谁受倒计时影响、Dora精确加成。 |
| 结算 | 只按实际成交价格转移现金和对应实例；拒绝无交易。 | 不涉及未知：这是连续游戏的必要一致性。 |

## 防止过拟合的验证方案（本项目提出，不是原作已知规则）

1. 从议价运行路径移除 `visit.price` 与录像 `quotes[].accepted` 的直接决定权；录像留作独立观察集。
2. 同一物品/顾客/随机种子，测试改变公开卡、隐藏卡、首报价、第二报价、购买时现金、植物及声誉；记录完整状态转换，不能只验证录像已成交价。
3. 测试失败交易不改变现金与所有权、已售出/未拥有物品不能再卖、拒绝后改标价只影响后来顾客、重载不重算既定交易。
4. 原版可运行时，在未用于拟合的至少两名同类顾客上测试价格区间；每次只改变一个变量。若只找到公开攻略，参数必须标 `provisional`，并与 `observed` 数据分开存放。
5. 补齐等待时间、重复错误卡、非单调报价、极端报价、公私移动、多轮报价再接受这几类反例。不能用同一函数生成阈值和期望断言。

## 现有代码对应缺口（读取时状态）

`src/engine.ts` 的 `offer()` 以 `visit.price` 和录像已接受标记判决；`accept()` 无反报价时也取录像成交价；`add()` 未区分顾客接受与正确性；`settle()` 缺少对应库存仍先加钱；`loadVisit()` 的可选余额回填取消玩家历史选择。上述不是“查不到原版系数”的小差异，而是必须先修复的系统结构问题。
